# 예측마케팅 자동화 엔진 구현 기획서

> 근거 자료: 『빅데이터를 활용한 예측마케팅 전략』(외머 아튼·도미니크 레빈, 마인드큐브, 2017)의 **2부 목차(5~13장)**와 **7장·8장·12장·13장 본문**(사용자가 제공한 OCR 텍스트).
> **주의**: 7장·8장·12장·13장 외의 장은 목차만 근거로 했습니다. 각 장의 세부 규칙(군집 유형, 점수 기준, 캠페인 구성)은
> 본문을 확인한 뒤 반영해야 합니다. 본문 확인이 필요한 항목은 `[본문확인]`으로 표시했습니다.
> 7장·8장·12장·13장 OCR 텍스트는 일부 문장이 깨져 있어, 수치와 정의는 책 원문과 대조가 필요합니다.
> 현재 코드 분석은 `WorkflowExecutionService`, `EventService`, `V1__initial_schema.sql`, `ListMember`를 직접 읽은 결과입니다.

## 1. 현재 엔진의 상태 (코드로 확인한 사실)

| 항목 | 현재 | 예측마케팅에 필요한 것 |
|---|---|---|
| 처리 방식 | 이벤트 1건이 들어오면 `EventService.processEvent`가 런칭된 워크플로우를 전부 순회하며 **즉시·동기** 실행 | 시간 기반(지연, 주기) 실행 |
| 조건 타입 | `list`(리스트 소속), `custom_event`(이벤트 이름 일치) 두 가지뿐 | 단계, 점수, 세그먼트, 구매 횟수·금액 조건 |
| 액션 타입 | `list`(추가/제거), `webhook`(알림봇 포함) | 대기(wait), 단계 변경, 점수 갱신 |
| 지연 실행 | **없음** (`@Scheduled`/`@EnableScheduling` 사용처 없음) | "구매 3일 뒤", "30일 미접속 시" 같은 시간 조건 |
| 고객 모델 | **없음**. 고객은 이메일 문자열이고 `list_members`에만 존재 | 고객 테이블, 구매 이력, 지표 |
| 이벤트 저장 | `event_logs.event_data`에 JSON 문자열(TEXT) | 구매 금액·상품 집계용 정규화 테이블 |
| 빈도 조건 | `frequency`, `frequency_period` 필드는 있으나 `evaluateEventCondition`이 **사용하지 않음** | "30일 안에 3회 방문" 같은 조건 |
| `actionLogic` | 정규화는 하지만 `executeActions`에서 **사용하지 않음** | - |
| 목표 조건 | 있음(`goal_groups`, 달성 시 액션 중단) | 전환 측정에 재사용 가능 |
| 중복 방지 | `workflow_processed_leads`는 워크플로우 **런칭 시 기존 리스트 구성원을 한 번 처리하는 비동기 작업**(`WorkflowService.processExistingLeadsForWorkflow`, `@Async`)에서만 쓰이고, 설정 `onlyFirstTime`이 켜진 경우에만 기록·조회합니다. 이벤트 수신 경로(`processEvent`)에는 중복 방지가 없습니다. 테이블은 워크플로우·이메일 조합에 유니크 제약이 있습니다 | 순환 구조의 재진입 정책, 재발송 주기 제어 |
| 마이그레이션 | Flyway, `V1`과 `V3`만 존재 (`V2` 없음) | 다음 번호를 정할 때 확인 필요 |

**결론**: 규칙 실행 뼈대는 있지만 **시간(지연·배치)**, **고객 데이터 모델**, **점수/단계 조건**이 없습니다. 예측마케팅 9개 전략은 대부분 이 세 가지 위에 올라갑니다.

### 2-1. 7장 본문 반영: 생애주기 세그먼트와 캠페인 규칙

책의 원칙은 "얻기 위해 주어라"입니다. 고객에게 가치를 먼저 제공해야 평생가치를 얻는다는 뜻이며, 생애주기 단계마다 목표와 메시지가 다릅니다(도표 7.2).

**세그먼트 정의와 시스템 판정 규칙**

| 세그먼트 | 책의 정의 | 시스템 판정(기본값, 설정 가능) | 마케팅 목표 | 메시지 콘셉트 |
|---|---|---|---|---|
| 예상고객 | 과거에 제품을 산 적이 없는 사람 | 구매 0회, 이메일 등 식별 정보 있음 | 구매 전환 | 도와드릴까요 |
| 신규고객 | 최초 구매 후 90일이 지나지 않음 | 구매 1회, 첫 구매 후 90일 미만 | 최대한 빠른 재구매 | 감사합니다 |
| 반복/활동 고객 | 2회 이상 구매 | 구매 2회 이상, 마지막 구매 후 90일 미만 | 지속 참여, 타인에게 추천 | 사랑합니다 |
| 이탈 위험/비활성 | 지난 90일 구매·이용 없음, 또는 구매 가능성이 높지 않음 | 마지막 구매 후 90일 이상 365일 미만 (점수 기준은 2단계) | 재참여 | 기억해주세요 |
| 유효기간 경과 | 지난 1년간 구매 없음, 또는 가능성 매우 낮음 | 마지막 구매 후 365일 이상 | 재활성화 | 보고 싶습니다 |

- **판정 우선순위**: 유효기간 경과 → 이탈 위험 → 반복/활동 → 신규 → 예상고객 순으로 먼저 맞는 단계에 배정합니다. 겹치는 경우(예: 구매 1회, 100일 경과)를 하나로 정하기 위한 제 판단입니다.
- 90일, 365일은 책의 예시 기준입니다. 책에서도 재구매 간격이 자동차(수년), 반려동물 사료(한 달 이하), 패션 세일(몇 주)처럼 회사마다 다르다고 하므로 **업종별로 설정 가능**해야 합니다.

**캠페인 규칙 (본문에서 추출)**

1. **최초 구매 직후가 가장 중요하다**: 유통에서 최초 구매자의 70%는 돌아오지 않고, 두 번째 구매를 하면 재구매 비율이 30%에서 70%로 오른다고 합니다(책 수치, 미국 유통 기준). 우리 데이터로 다시 측정해야 하므로 기본값으로만 씁니다.
2. **허니문 기간**: 첫 구매 후 일정 기간(예시 2개월) 안에 재구매가 없으면 이후에도 없을 가능성이 높습니다. 기간이 지나면 추가 인센티브를 제공합니다(책의 예시는 60일). 이 기간은 설정값입니다.
3. **소모품 리마인드**: 제품이 소진되기 **최소 1주일 전**에 알림을 보냅니다. 고객별 예상 재구매일이 필요합니다. 1단계에서는 고객 본인의 구매 간격 중앙값(구매 2회 이상일 때)을 쓰고, 없으면 상품 기본 주기를 씁니다. 책은 이 주기를 예측 알고리즘으로 구하라고 하며, 그 모델은 3단계입니다.
4. **구매 직후 메시지 구성**: 감사 → 제품 사용·관리 팁 → 문제 없는지 확인(상담 연락) → 연관 상품 추천(추천은 10장).
5. **반복/활동 고객도 방치하지 않는다**: 감사 표시(예: 상위 1%·5%·10% 고객에게 안내), 아직 이용하지 않은 새 카테고리 소개, 지인 추천 유도. 여러 카테고리를 쓰는 고객의 미래 가치가 높으므로 `category_count` 지표를 둡니다.
6. **개인별 발송 주기 존중**: 연 2회 몰아서 사는 고객에게 매달 리마인드를 보내면 의미가 없습니다. 발송 빈도 상한을 고객의 구매 주기에 연동합니다.
7. **자동 수신 제외 금지**: 사례 기업이 한동안 메시지를 열지 않은 고객을 임의로 발송 목록에서 뺐다가 항의를 받았습니다. 비활성이라는 이유만으로 자동 제외하지 않고, 수신 거부는 고객 요청이나 설문 응답으로만 처리합니다.
8. **인센티브는 시간과 가치에 따라 키운다**: 비활성·유효기간 경과 고객은 시간이 지날수록 돌아오기 어려우므로 단계별로 혜택을 올립니다. 평생가치가 높은 고객일수록 큰 혜택을 줍니다(사례: 반려동물 용품 업체). 가치별 차등은 고객가치 점수가 있는 2단계부터 가능합니다.
9. **비용이 큰 채널은 가능성 높은 고객에게만**: 사례 기업은 우편물을 구매 가능성이 높은 고객에게만 보냈습니다. 알림톡도 건당 비용이 있으므로 같은 원칙을 적용합니다.
10. **채널 전환**: 1년 동안 이메일에 반응이 없는 고객에게는 같은 채널을 반복하지 말고 우편이나 광고 맞춤 타깃을 씁니다. 현재 시스템은 알림톡 웹훅이 전부이고 이메일 열람 데이터가 없으므로 4단계(내보내기)에서 다룹니다.
11. **원인 파악**: 비활성 고객에게는 가정하지 말고 설문으로 이유를 묻습니다. 기업 대상(B2B)에서는 사용량 감소가 재계약 이탈의 신호입니다(제품 사용 이벤트가 있을 때만 적용).

**단계별 워크플로우 템플릿 초안** (대기 후 발송 전에 목표 조건을 다시 평가해야 함)

| 템플릿 | 트리거 | 흐름 |
|---|---|---|
| 신규 환영 | 구매 이벤트(첫 구매) | 즉시 감사 → 1일 후 환영·사용 팁 → 1주 후 후속·후기 요청 → 1개월 후 연관 상품·맞춤 할인 → (허니문 기간 경과 시 재구매 없으면) 인센티브. 12장의 1일/1주/1개월 예시를 따랐고 시점은 테스트로 조정 |
| 소모품 리마인드 | 예상 재구매 시점 (주기의 %, 또는 N일 전) | 리마인드 메시지 (통제 그룹 포함, 2-2절) |
| 반복 고객 감사 | 단계가 '반복/활동'으로 변경 | 감사 → 새 카테고리 소개 → 지인 추천 안내 |
| 비활성 복귀 | 단계가 '이탈 위험'으로 변경 | 만족도 설문·개인 추천 → 14일 후 미구매 시 소액 쿠폰 → 30일 후 더 큰 쿠폰 (일수는 설정값) |
| 유효기간 경과 복귀 | 단계가 '유효기간 경과'로 변경 | 큰 할인 제안 → 다른 채널용 리스트 내보내기 |

기존 `goal_groups`(목표 조건 충족 시 액션 중단)를 재사용하면 "재구매하면 이후 발송 중단"을 구현할 수 있습니다. 다만 현재는 이벤트가 들어온 시점에만 목표를 평가하므로, 예약 건이 실행되는 시점에도 다시 평가하도록 바꿔야 합니다.

### 2-2. 12장 본문 반영: 구매 후 프로그램, 사은 캠페인, 충성도 프로그램

**확대된 고객유입 퍼널 (그림 12.1)**

| 구분 | 퍼널 단계 | 적용 전술 (책의 표기) |
|---|---|---|
| 구매 전 | 인지 → 육성 → 자격충족 → 평가 → 구매 | 행동 기반 타깃팅, 검색 리타깃팅, 사이트 리타깃팅 |
| 구매 후 | 참여 → 확장 → 갱신 | 충성도 프로그램, 유효기간 경과 사용자 타깃팅 |

- 책의 요지는 퍼널이 구매에서 끝나지 않고 구매 후(참여, 확장, 갱신)까지 이어진다는 것입니다. 이미 돈을 낸 고객에게서 더 받는 것이 신규 고객을 얻는 것보다 쉽다고 합니다.
- 구매 후 단계는 7장의 생애주기 5단계(신규, 반복/활동, 이탈 위험, 유효기간 경과)로 구현합니다. 구매 전 단계(인지~평가)는 예상고객을 행동(가입, 조회, 장바구니)으로 세분하는 것이라 11장의 리마케팅과 함께 4단계에서 다룹니다.
- **그림 12.1 도형 확인** (사용자가 제공한 사진 기준): 모양은 **모래시계**입니다. 위쪽 역삼각형에 구매 전 5단계가, 가운데 잘록한 곳에 `$`(구매·결제 시점)가, 아래쪽 삼각형에 구매 후 3단계가 있습니다. 아래 삼각형 양옆의 **순환 화살표**는 갱신에서 다시 참여로 돌아오는 반복을 나타냅니다. 즉 구매 후는 한 번 지나가는 깔때기가 아니라 **되풀이되는 고리**입니다.
- 도형 왼쪽에 위에서 아래 순서로 적힌 전술은 행위 기반 타깃팅, 검색 리타깃팅, 사이트 리타깃팅, 고객 충성도 제고 프로그램, 유효기간 경과 사용자 타깃팅입니다. 사진이 비스듬해서 각 전술이 어느 단계 높이에 정확히 대응하는지는 단정하지 않습니다. 앞의 세 가지는 구매 전, 뒤의 두 가지는 구매 후로 읽힙니다.
- 본문에서 도형을 요약한 문장("참여 ... 투자 ... 제안 ... 처음부터 다시 반복")은 여전히 OCR이 깨져서 정확한 단어를 확인하지 못했습니다. 도형의 순환 화살표와 같은 뜻으로 보입니다. `[본문확인]`
- 구매 전 5단계를 커머스 데이터에 대응시키는 안(제 제안, 책의 정의 아님): 인지=사이트 첫 방문·유입, 육성=이메일·알림톡 수신 동의, 가입, 콘텐츠 반응, 자격충족=구매 의사 신호(상품 반복 조회, 장바구니) 점수 기준 충족, 평가=쿠폰·가격 확인, 비교 행동. `[책의 정의 확인 필요]`

**구매 후 프로그램 규칙**

1. **구매 직후가 효과적이다**: 구매 직후 짧은 기간에 고객은 아직 필요가 남아 있고 브랜드가 신선하게 느껴 후속 구매가 잘 일어납니다. 구매 이벤트로 바로 시작합니다.
2. **환영 캠페인**: 감사, 환영, 다음 구매용 맞춤 할인, 기한 있는 무료배송이나 다음 구매 시 사은품, 후기 작성·공유 요청을 담습니다. 구매 후 1일, 1주, 1개월에 나눠 보내는 방식이 예시이며, 최적 시점과 내용은 업종마다 달라 테스트가 필요합니다.
3. **구매 후 추천 메시지는 모든 구매에 보낸다**: 첫 구매뿐 아니라 재구매에도 감사, 사용 팁, 할인·추천을 보냅니다. 소비자 대상은 할인 여부를 **고객가치**로 정하고(가치가 높을수록 더 투자), 기업 대상은 다음 판매보다 초기 구매의 가치를 얻도록 돕는 것을 먼저 합니다.
4. **환영 캠페인의 개인화**: 첫 구매 시점에 미래 가치를 예측하면 세그먼트별로 제안을 다르게 할 수 있습니다. 가치가 높은 고객은 특별하게 대우합니다. 예측값은 2단계부터 사용합니다.
5. **구매 외 날짜를 기준으로 한 발송**: 청소 서비스 사례는 예약 직후 이메일, 방문 3일 전 문자, 당일 문자와 피드백 이메일, 한 달 뒤 고객·담당자 이름과 할인이 담긴 후속 이메일을 보냅니다. `wait` 액션이 이벤트 발생 시각뿐 아니라 이벤트 데이터의 날짜 필드(예: 예약일)를 기준으로도 동작해야 합니다.
6. **재보충(리필) 알림은 가장 성과가 좋은 캠페인이다**: 책 수치로 개봉률 20~50%, 구매율 최대 30%이고 다른 캠페인의 최대 4배입니다. 시점을 정하는 세 가지 방법과 우선순위는 다음과 같습니다.
   - 1순위 개별 고객의 과거 재구매 주기 → 2순위 전체 고객 평균(대중의 지혜) → 3순위 운영자가 수동 입력
   - 같은 상품도 미용실은 매주, 일반 소비자는 3개월마다일 수 있어서 개별 데이터가 가장 정확합니다.
   - 사례 1: 주기가 60일인 상품에 45일째 알림 → 평균 매출 200% 향상
   - 사례 2: 신발은 소모품이 아니지만 마모 주기가 예측 가능해 18개월 전 구매 고객에게 추천 → 통제 그룹 대비 개봉률 +5%p, 사이트 방문 +15%, 방문당 상품 조회 +19%
   - 7장은 "소진 1주 전", 이 사례는 주기의 75% 시점이어서 기준이 다릅니다. 시점은 **주기의 몇 % 또는 N일 전** 중 선택하는 설정값으로 두고 테스트합니다.
7. **통제 그룹이 필요하다**: 사례에서 효과를 무작위 통제 그룹과 비교해 측정했습니다. 워크플로우마다 홀드아웃 비율(예: 10%는 발송하지 않고 전환만 추적)을 설정할 수 있어야 합니다.
8. **신제품·재고 소개는 관심 있는 고객에게만**: 전체 발송 대신 관심이 있을 고객을 예측해 보냅니다. 재고 사례(사이즈 6과 12만 남은 드레스)는 상품 속성(사이즈)과 고객의 사이즈·관심 정보가 필요합니다. 4단계입니다.
9. **고객이 말한 선호보다 행동**: 출판사가 뉴스레터 신청 시 고른 선호 장르 대신 구매·열람 행동 기반 군집으로 발송 대상을 정했더니 개봉 2배, 클릭 4배, 전환 7배였습니다. 세그먼트는 폼 응답보다 행동을 우선합니다(3단계 군집).

**사은 캠페인과 고가치 고객**

10. **상위 고객에 집중**: 책의 관찰로는 매출의 60% 이상, 이익의 90% 이상이 고객의 약 20%에서 나옵니다. 보상은 돈이 아니어도 됩니다(신상품 사전 공개, 초청 행사, 대표 명의 개인 메시지·전화, VIP 전용 상담, 명절 선물).
11. **충성도에는 4가지 유형이 있고 프로그램이 다르다**: 거래 기간, 지출액, 카테고리 다양성, 추천·영향력. 지표 4개(`tenure_days`, `monetary`, `category_count`, `referral_count`)를 둡니다.
12. **가치 높은 고객도 행동이 다르다** (아웃도어 업체 사례의 4개 페르소나)

| 페르소나 | 특징 | 책의 대응 예 |
|---|---|---|
| 되돌아오지 않는 대량 구매자 | 한 번 크게 구매하고 미복귀, 고가 용품, 고급 브랜드, 연말·기념일 광고로 유입 | 구매한 텐트·유모차에 붙일 수 있는 물병을 크리스마스 선물로 발송 |
| 보상 중독자 | 약 2개월마다 정확히 구매, 포인트 많이 사용, 반품 주저 없음, 재고정리 세일 구매 → **마진 낮음** | `[본문확인]` 붙여주신 텍스트에 캠페인 사례 없음 |
| 보수적 고객 | 오프라인 위주, 주말 방문, 재고정리 세일, 신발류, 매장 근처 거주 | 새 신발 모델을 알리는 엽서·전화 |
| 타락 천사 | 첫 두 달에 3건 이상 구매하고 평균 구매액이 평균의 약 2배, 몇 달 뒤 구매 중단, 반품 의향 높음 | `[본문확인]` 붙여주신 텍스트에 캠페인 사례 없음 |

   - 가치는 매출이 아니라 **마진** 기준으로 봐야 합니다(반품, 포인트 사용, 할인 구매 반영). 지표에 `return_rate`, `discount_purchase_ratio`를 둡니다.
   - 군집 모델이 없는 초기에는 규칙으로 근사할 수 있습니다. 예를 들어 타락 천사는 "첫 60일에 3건 이상 구매 후 90일 이상 구매 없음", 되돌아오지 않는 대량 구매자는 "1회 구매 금액이 상위 10% 이상이고 이후 180일 구매 없음"입니다. 이 기준값은 제 제안이며 책에 있는 수치가 아닙니다.

**충성도 프로그램**

13. **개별 고객 식별이 핵심 가치**: 보상의 금전 가치보다 개별 행동 데이터의 가치가 훨씬 큽니다.
14. **개인별 목표 금액**: 의류업체 마비는 평균 100달러를 쓰는 고객에게 "150달러 쓰면 추가 포인트", 평균 300달러 고객에게 "400달러"를 제시해 고객당 방문 횟수를 1.2회에서 2.1회로 늘렸습니다. 목표 금액은 고객별 평균 주문액의 약 1.3~1.5배입니다(책 예시 비율). 이 계수는 설정값입니다.
15. **최근 흐름 3가지**: (1) 공식 가입 없이도 행동으로 추적하고, 미래에 VIP가 될 행동을 보이면 첫날부터 특별 대우 (2) 모두에게 같은 혜택이 아니라 개인별 맞춤 (3) 구매뿐 아니라 구매를 예고하는 행동(탐색, 친구 추천, SNS 게시)에도 보상
16. 포인트 제도를 직접 운영할지는 별도 결정이 필요합니다. 운영하지 않는 고객사에는 쿠폰이나 적립금 발급 웹훅으로 연동하고, 포인트 원장 모듈은 4단계 선택 사항으로 둡니다.

**옴니채널**

17. 온라인 첫 구매자의 28%가 이후 오프라인에서도 사고, 오프라인 시작 고객의 22%가 온라인으로 넘어옵니다. **이용 채널 수는 평생가치의 강력한 예측 변수**입니다. 한 게임 유통업체는 매장 구매자의 60%가 구매 전에 웹·모바일 사이트를 방문했다고 합니다.
18. 화장품 업체 사례: 고객 위치 분석으로 새 매장 위치를 정했고, 구매 가능성과 평생가치가 높은 고객 중 매장 반경 50마일 이내에 사는 고객에게 초청장을 보내고 개장 2일 전에 리마인드해 개장 후 판매가 평균 일일 판매량의 7배가 되었습니다. 예측 모델로 다이렉트 메일 대상을 고른 캠페인은 수익이 163% 올랐습니다.
19. 구현 조건: `purchases.channel`(온라인/오프라인), `customers.region`, `channel_count` 지표, 지역과 점수를 함께 쓰는 세그먼트. 4단계입니다.

**책의 성과 수치 (미국 기준, 대시보드 비교용 참고값)**

| 캠페인 | 개봉률 | 구매·전환율 |
|---|---|---|
| 환영 이메일 | 35% 이상 | 구매율 10% 이상 |
| 구매 후 이메일 | 30% 이상 | 전환율 약 8% |
| 재보충 알림 | 20~50% | 구매율 최대 30% |

우리 환경에서 같은 수준이 나온다는 보장은 없으므로 목표값이 아니라 참고값으로만 씁니다.

### 2-3. 13장 본문 반영: 고객 유지, 이탈 관리, 재활성화

**유지와 이탈을 재는 방법**

| 지표 | 정의 | 책의 권고·사례 |
|---|---|---|
| 금전적 유지율 | 측정 기간 동안 유지한 고객의 **금액** 비율 | 고객 수 유지율만 보면 지표는 좋은데 사업 성과는 나쁜 상황이 생길 수 있어 금액 기준을 권장. 8장의 가치 세그먼트별로 측정 |
| 순 역이탈(negative churn) | 잃은 매출보다 기존 고객의 추가 매출(상향·교차 판매, 추가 사용)이 더 많은 상태 | 100달러를 잃고 150달러를 더 얻으면 순 50달러 역이탈. 고객 100명 중 10명을 잃어도 남은 90명에게서 더 많은 매출이 가능 |
| 고객 기간별 이탈률 | 첫 구매·가입 후 기간별 이탈률 | 신규 고객의 이탈률이 높아서, 신규 비중이 크면 총 이탈률이 높게 보임. 골프 코스 사례는 업계 평균과 유지율이 같은데 빠른 성장 탓에 신규가 많아 나빠 보였음 |
| 가치 세그먼트별 이탈률 | 지출 구간별 이탈률 | 유통업체 사례: 활동 고객이 22% 줄었는데 1천 달러 미만은 34%, 1천~1만 달러는 15% 줄고, 1만~5만 달러는 1% 감소, 5만 달러 초과는 오히려 16% 증가. 고객 수와 매출이 줄어도 수익성은 올랐음 |
| 가치 감소 | 고객이 전년보다 적게 지출 | 은행 사례: 계좌 수는 5% 증가·이탈 4.1%로 안정적인데 평균 잔액이 매년 2% 감소했고, 가치 감소의 손실이 계좌 감소 손실의 3배. 가치가 줄어드는 고객 세그먼트를 따로 만들어 모니터링 |

- **모든 이탈이 같지 않습니다.** 수익성 낮은 고객의 이탈은 최우수 고객의 이탈만큼 나쁘지 않습니다. 이탈 경보는 고객 수가 아니라 **가치를 가중**해서 봐야 합니다.
**도표 13.2 확인** (사용자가 제공한 사진 기준)

| 고객 기간 | 골프기어 비중 | 골프기어 이탈률 | 경쟁사 비중 | 경쟁사 이탈률 |
|---|---|---|---|---|
| 0-4개월 | 30% | 30% | 5% | 30% |
| 5-12개월 | 25% | 10% | 10% | 10% |
| 1-2년 | 40% | 5% | 50% | 5% |
| 3년 이상 | 5% | 2% | 35% | 2% |

이 엔진이 다루는 것은 타깃팅된 두 가지입니다. 길들임을 막기 위해 고객당 인센티브 제안 사이에 최소 간격을 둡니다.

**선제적 유지 규칙**

1. 이탈 예방은 마지막 순간 붙잡기나 재활성화보다 쉽고 저렴하며 효과적입니다.
2. **경고 신호**: 웹사이트 방문이나 이메일 개봉 감소, 제품·서비스 소비량 감소, (소프트웨어) 평소보다 적은 사용 세션. 이탈한 고객들이 이탈 전에 보인 공통 행동을 찾아 새 고객이 같은 행동을 보이면 경고합니다. 구현은 `activity_trend`(최근 N일 활동량 ÷ 직전 N일 활동량)입니다. 방문·세션 이벤트가 수집되는지는 미확인이고, 메시지 열람 데이터는 현재 없습니다.
3. **핵심 행동 발견**: 온라인 서비스 사례에서 핵심 기능 5개 중 2개를 쓰는 고객의 유지율이 하나도 안 쓰는 고객보다 40% 높았습니다. 이를 모든 고객에게 처음부터 알리고 미사용 고객에게 개인화 이메일을 보내 전체 이탈률이 1년 만에 10%p 떨어졌습니다. 우리 쪽은 유지율과 상관이 높은 행동(예: 2개 이상 카테고리 구매)을 데이터로 찾고 미이행 고객에게 안내하는 방식으로 일반화합니다.
4. **소비자 대상 접촉**: 간단한 리마인드, 맞춤 추천, 가격 할인, 선물, 세일·이벤트 초대. 구매 가능성은 낮지만 예상 평생가치가 높은 고객에게 다음 구매 20% 할인을 제안하는 것이 예시입니다. 기업 대상은 적절한 시점에 전화로 도움을 제안합니다.
5. **불만 이벤트**: 불만을 제기한 고객의 이탈률이 높았습니다(사례: 한 달간 불만 고객의 약 10%가 다음 달 이탈). 콜센터·문의 접수를 `complaint` 이벤트로 받아 즉시 대응 워크플로우를 시작합니다. 불만이 잘 해결되면 평생 고객이 되는 일도 드물지 않다고 합니다.
6. **구매 제품·카테고리 수**: 많이 살수록 유지율이 높습니다(케이블 TV만 쓰는 고객의 이탈률이 TV·인터넷·전화를 모두 쓰는 고객의 2배 이상). `category_count`를 이탈 점수에 반영하고 교차 판매를 유지 전략으로 씁니다.
7. **근본 원인 확인**: 제품 문제, 서비스 불량, 사용법을 몰라서, (기업 대상) 담당자 교체 등 원인에 따라 대응이 다릅니다. 예측 모델은 이탈 점수와 함께 **점수에 영향을 주는 요소의 순위**를 줍니다. 소비자 서비스 업체 사례는 ① 매일 고객별 이탈 점수 산정 ② 영향 요소 파악과 대응 전략 수립 ③ 전략별 효과 테스트로 유지율을 10% 높였습니다. 요소의 예는 콜센터 통화 횟수입니다. 불만이 큰 고객에게는 재전화 후 계약 연장 시 유지보수나 할인을, 가격에 민감한 오랜 고객에게는 계약 종료 몇 주 전 선제 전화로 수용 가능한 가격을 협의했습니다.
8. **인센티브는 가치에 비례**: 과거에 가치가 컸던 고객일수록 많이, 신규 고객은 예상 평생가치에 비례해 지출합니다.
9. **꾸준한 참여가 소비량보다 중요**: 구독 갱신 사례에서 몇 차례 몰아서 많이 소비하는 고객이 적은 양이라도 꾸준히 소비하는 고객보다 갱신 가능성이 낮았습니다. 그래서 고객마다 최소 한 달에 한 번 관련 콘텐츠를 보내고, 추천 엔진 기반 자동 이메일이 비용 대비 효과가 좋았으며, 상담 통화 같은 고비용 수단은 프리미엄 고객에게만 썼습니다. `engagement_regularity`(최근 6개월 중 활동한 달 수)와 비용 단계별 대상 제한을 둡니다.

**유지 지출 한도 공식**

```
X = Y(%) × LTV
X: 쓸 수 있는 금액, Y: 캠페인으로 보존할 수 있는 고객 비율, LTV: 보존한 고객의 평생가치
```

- 책의 예: 불만 고객의 이탈률 10%, 평생가치 250달러. 프로그램이 이탈률을 10%에서 5%로 낮추면 Y=5%이므로 X=12.5달러. Y를 모르면 이탈률 전부(10%)를 막는다고 가정한 25달러가 상한입니다. 실제 Y는 작은 규모의 테스트로 구합니다.
- **해석 주의**: 12.5달러는 5%×250으로 계산되므로 캠페인 **대상 고객 1명당** 한도로 읽힙니다(본문은 "각 고객을 유지하기 위해"라고 표현). `[본문확인]`
- 구현: 인센티브를 쓰는 액션에 `max_incentive`를 두고 발송 전에 한도를 넘는지 검사합니다. Y는 테스트로 측정하고, 측정 전에는 해당 세그먼트의 이탈률을 상한으로 씁니다.

**테스트 설계 (본문의 권고 순서)**

① 이탈과 관련된 고객 변수에 대한 가설을 세운다 → ② 이탈 위험 고객 대상 테스트 프로그램을 설계한다 → ③ 대상 세그먼트를 **인센티브를 받지 않는 그룹을 포함해 둘 이상으로 나눈다** → ④ 이탈 감소와 인센티브 회수는 테스트로만 계량화할 수 있다 → ⑤ 결과로 프로그램을 개선한다. 12장의 통제 그룹과 같은 방식이므로 `workflow_holdouts`로 구현하고, 그룹 간 이탈률·매출을 비교하는 리포트를 둡니다.

**재활성화 캠페인**

- **정의**: 12개월 동안 구매하지 않으면 유효기간 경과로 봅니다(유료 가입은 만료 시). 7장의 365일 기준과 같습니다.
- **비용**: 책이 인용한 데이터로 유효기간 경과 고객을 되살리는 비용은 신규 획득의 평균 10분의 1입니다.
- **제안은 관대하게**: 이미 폐기된 고객이라 잃을 것이 없어서 다음 구매 시 상당한 할인을 제안합니다. 좋아하던 제품 유형을 추천한 사례는 월 매출이 8배가 됐습니다.
- **재활성화된 고객은 신규처럼 행동한다**: 생애주기를 거의 다시 시작하고, 직후에 다시 유효기간이 경과할 가능성이 높아 특별한 주의가 필요합니다. `reactivated_at`을 기록하고, 재활성화 후 설정 기간(기본 90일) 동안은 환영 시퀀스를 다시 적용하며 재이탈 위험을 감시합니다. 7장의 판정 규칙(구매 2회 이상이면 반복/활동)과 충돌하므로 이 기간에는 '재활성화 신규'를 우선하자는 것은 제 제안입니다.
- **4단계**
  1. 대상 결정: 수익성 있는 고객, 팔고 싶은 제품에 관심 있는 고객. 제외 예는 주문 대비 5% 이상 반품한 고객, 30% 이상 할인받은 고객입니다(기본값, 설정 가능).
  2. 수용 가능성이 높은 후보만 선택: 다이렉트 메일·타깃 광고처럼 비용이 큰 채널일수록 엄격하게. 아직 준비되지 않은 고객에게 보내면 지나치게 적극적으로 보여 오히려 멀어질 수 있습니다.
  3. 여러 채널로 재접촉: 이메일, 엽서, 앱 알림. 접촉 횟수가 많을수록 대개 반응률이 높습니다.
  4. 과거 구매 내역, 반응한 것, 선호 브랜드로 개인화하고, 이탈 원인을 파악해 극복하는 제안을 합니다.
- 2번(준비된 고객만)과 3번(접촉을 많이)이 서로 당기므로, 구매 가능성 점수 임계값과 채널별 빈도 상한을 함께 두는 것을 제안합니다(제 판단).

### 2-4. 8장 본문 반영: 가치 기반 마케팅

모든 고객이 같은 가치를 갖는 것은 아닙니다. 자주 반품하는 고객은 그로 인한 비용이 매출보다 클 수 있습니다. 8장은 평생가치(LTV)로 고객을 나누고 가치별로 전략과 서비스 수준을 다르게 하는 **가치 기반 마케팅**을 다룹니다. 그림 8.1과 도표 8.2~8.4는 사용자가 제공한 사진으로 확인했습니다.

**가치 세그먼트 분류**

- 고객을 매출 또는 수익성 순으로 줄 세워 **상위 10% = 높은 가치(VIP), 다음 60% = 중간 가치, 하위 30% = 낮은 가치(수익성 낮음)**로 나눕니다.
- 금액 기준(예: 연 500달러 이상)이 아니라 **비율**로 나누는 이유는 세그먼트의 비중을 항상 같게 유지하고 세그먼트별 평균 가치가 어떻게 변하는지 추적하기 위해서입니다. 유지 지표를 같은 비율의 모집단에서 계산하므로 세그먼트 평균이 변해도 영향받지 않습니다.
- 10/60/30은 수학적 근거보다 비즈니스상의 선택이고, 가치 분포를 보고 다른 비율로 나눠도 됩니다. **설정값**으로 둡니다.
- 책의 사례: 의류 유통업체의 활동 고객 평균 지출이 높은 가치 600달러, 중간 가치 120달러, 낮은 가치 30달러였습니다. 이익 기여는 상위 10%가 30~40%에 가깝고 중간 가치가 60~70%, 낮은 가치가 0~10%라고 합니다(본문 표기 그대로).
- 가치는 과거 12개월의 실제 값을 쓰고, 예측 지표가 있으면 향후 12개월의 예상 값으로 대신합니다. 매출보다 **마진** 기준을 권합니다(12장과 같은 이유로 반품 비용 등을 반영).

**가치 기반 전략 (그림 8.1)**

| 세그먼트 | 초점 | 도표의 내용 | 우리 구현 |
|---|---|---|---|
| 높은 가치 | 유지 | 존중하고 유지하기 위해 돈을 쓴다. 니즈가 반드시 충족되게 한다(예: 서비스 수준). 유지 프로그램에 필요한 만큼 투자한다(예: 서비스 보증). 유지 지표에 주의한다 | VIP 리스트, 유지 워크플로우, 인센티브 상한(2-3절 공식) |
| 중간 가치 | 가치 증대 | 상향 판매로 잠재력을 키운다. 전면적인 서비스 "솔루션" 제공자, 제품 라인 확장, 고객 전문가 되기, 빈번한 구매에 대한 우대 프로그램. 구매 상승 잠재력에 세심한 주의 | 카테고리 확장 캠페인, 구매 빈도 우대 |
| 낮은 가치 | 교정 또는 관리 | 서비스 비용을 줄인다. 가격을 올리거나 과거에 무료였던 것에 요금을 부과, 서비스 수준을 낮춤, 고객 획득 전략을 수정 | 저비용 채널만 사용, 프로모션 제외, 서비스 플래그 |

도표 왼쪽에는 위에서 아래로 세 가지 원칙이 있습니다. ① 우선순위에 따라(최고 가치 세그먼트를 우선으로) 희소한 자원을 배정 ② 세그먼트의 반응률과 매출 금액에 근거해 마케팅 프로그램을 맞춤화 ③ 니즈와 지불 의사에 근거해 서비스 수준과 속성을 차별화. 세그먼트마다 하나씩 대응하는지 전체에 적용되는 원칙인지는 도표만으로 단정하기 어려워 전체 원칙으로 읽었습니다(제 해석).

**가치 변화 과정 (도표 8.2~8.4)**

도표 8.2는 **최근 12개월 가치 상태(행)**와 **이전 12개월 가치 상태(열)**를 비교하는 교차표이고 칸마다 1~7번 세그먼트가 적혀 있습니다. 예측 지표를 쓰는 경우에는 최근 12개월 대신 향후 12개월 예상 가치를 씁니다.

| 번호 | 세그먼트 | 판정 (이전 12개월 → 최근 12개월) | 책의 설명 |
|---|---|---|---|
| 1 | 두 기간 모두 비활성 | 주문 없음 → 주문 없음 | 장기간(예: 24개월 이상) 비활성. 해마다 늘지만 재활성화할 기회가 있음 |
| 2 | 재활성화 | 주문 없음 → 높음/중간/낮음 | 비활성이다가 최근 되살아남. 유효기간 경과 고객 대상으로 쓴 비용을 상쇄함 |
| 3 | 안정적 | 같은 가치 세그먼트 유지 | |
| 4 | 유효기간 경과 | 높음/중간/낮음 → 주문 없음 | 높은 가치 고객의 경과가 낮은 가치 고객의 경과보다 훨씬 나쁨. 낮은 가치 고객이 수익성에 부정적이면 차라리 없는 편이 나을 수도 있음 |
| 5 | 가치 성장 | 낮음 → 중간·높음, 중간 → 높음 | 충성도와 가치가 늘고 있음 |
| 6 | 가치 하락, 이탈 위험 | 높음 → 중간·낮음, 중간 → 낮음 | 악화 리스크 신호 |
| 7 | 신규(예상 고객에서 전환) | 신규 → 높음/중간/낮음 | 최근 획득한 고객과 그들이 가졌거나 가질 것으로 예상되는 가치 |

**도표 8.3 예** (행 = 최근 12개월, 열 = 이전 12개월, 사진 기준)

| 최근 \ 이전 | 주문 없음 | 높은 가치 | 중간 가치 | 낮은 가치 | 신규 고객 | 합계 |
|---|---|---|---|---|---|---|
| 주문 없음 | 20,000 | 1,000 | 14,000 | 20,000 | - | 55,000 |
| 높은 가치 | 1,000 | 15,000 | 2,000 | 1,000 | 3,000 | 22,000 |
| 중간 가치 | 9,000 | 5,000 | 96,000 | 3,000 | 14,000 | 127,000 |
| 낮은 가치 | 2,000 | 2,000 | 18,000 | 38,000 | 4,000 | 64,000 |
| 합계 | 32,000 | 23,000 | 130,000 | 62,000 | 21,000 | 268,000 |

- 본문 설명과 일치합니다. 높은 가치였던 1,000명이 유효기간 경과했고, 획득한 21,000명 중 3,000명이 높은 가치입니다.
- 7개 세그먼트 인원을 도표 8.2의 칸 번호로 계산하면(제 계산, 합계 268,000으로 검증) 1번 20,000, 2번 12,000, 3번 149,000, 4번 35,000, 5번 6,000, 6번 25,000, 7번 21,000입니다. 가치가 하락하는 고객(25,000)이 성장하는 고객(6,000)의 4배가 넘는 것이 이 예시의 경고 신호입니다.

**도표 8.4 순손익 예** (사진 기준)

| 세그먼트 | 재활성화 | 신규 | 기간경과 | 순변화 | 고객당 지출 | 순손익 가치 |
|---|---|---|---|---|---|---|
| 높은 가치 | 1,000 | 3,000 | -1,000 | 3,000 | $600 | $1,800,000 |
| 중간 가치 | 9,000 | 14,000 | -14,000 | 9,000 | $120 | $1,080,000 |
| 낮은 가치 | 2,000 | 4,000 | -20,000 | -14,000 | $15 | -$210,000 |
| 합계 | 12,000 | 21,000 | -35,000 | -2,000 | | $2,670,000 |

- 순변화는 재활성화 + 신규 + 기간경과이고, 순손익 가치는 순변화 × 고객당 지출입니다. 도표 8.3의 재활성화(1,000/9,000/2,000), 기간경과(1,000/14,000/20,000), 신규(3,000/14,000/4,000)와 정확히 일치하고, 합계 267만 달러도 계산과 맞습니다.
- **소리 없는 감소**: 같은 수의 고객을 획득·재활성화해도 가치가 낮으면 기업 가치가 줄 수 있습니다. 이 예에서는 활동 고객이 2,000명 줄었지만 높은 가치 고객을 더 지켜서 고객가치가 267만 달러 늘었습니다.
- 낮은 가치 고객당 지출이 표에서는 $15, 앞의 사례 문단에서는 30달러입니다. 표의 합계(267만 달러)는 $15로 계산해야 맞으므로 표의 값을 그대로 썼습니다.
- 구현: 12개월 창 두 개(이전, 최근)의 가치 세그먼트를 비교해 매월 또는 분기마다 교차표, 7개 세그먼트 인원, 순손익 가치를 계산합니다. 6번(가치 하락)은 이탈 위험 경보에, 2-3절의 가치 감소 지표와 연결합니다.

**높은 가치 고객 유지 규칙**

1. 최근까지 많은 기업이 최고 고객을 식별조차 못 했습니다. 소수 고객이 매출 대부분을 차지하는 사례가 많습니다(화장품 유통업체는 매출 50%가 고객 20%에서, 반짝 세일 사이트는 일부 고객이 연 10만 달러 이상, 주택 자가수리 사이트는 일부 고객이 평균의 20배 이상 소비, 맥도날드는 주 3~5회 먹는 18~34세 남성이 전체 판매량의 77%).
2. 사례: 주택 자가수리 사이트는 큰손 고객에게 CEO가 직접 전화했고, 반짝 세일 사이트는 최상위 1%(수익의 20%)에게 크리스마스 초콜릿을 보냈으며, 기술 기업 두 곳은 손으로 쓴 짧은 편지로 유명합니다.
3. 항공사 사은 프로그램은 비행 거리가 아니라 **지출 금액**을 기준으로 해서 더 많이 낸 고객이 자동으로 더 큰 보상을 받습니다. 우리 보상 등급도 지출 금액(또는 마진) 기준으로 합니다.
4. 유지 예산으로 선제적으로 유지하고, 미래 평생가치를 정확히 예측할 수 있으면 유지에 무엇이 필요한지 실험합니다. 일부 기업은 별도의 마케팅 계획이나 팀("고객 마케팅", "고객 성공")을 둡니다. 현재 고객이 더 자주 쓰게 하는 것이 신규 획득보다 훨씬 쉽습니다.

**중간 가치 고객 성장 규칙**

1. 목표는 높은 가치 그룹으로 끌어올리는 것입니다. 이미 사는 제품을 더 사게 하고, 좋아할 다른 제품·카테고리를 예측합니다.
2. 같은 1,000달러라도 가구 한 가지에만 쓴 고객보다 가구, 의류, 주방용품 세 카테고리에 쓴 고객의 미래 가치가 더 큽니다. `category_count`를 성장 잠재력 지표로 씁니다.
3. 기존 고객에게 새 제품·서비스를 제공하는 데는 비용이 덜 듭니다. 고객 지식으로 다음에 필요한 것을 제안하지 못하면 경쟁사에 문을 열어두는 셈입니다.
4. 사례: 의류업체 마비는 진 애호가 중 특정 상의를 선호하지만 아직 그 상의를 팔아본 적 없는 세그먼트를 찾아 별도 캠페인을 했고 평생가치가 36% 올랐습니다. 베이커리 업체는 핵심 고객이 나이 들며 저지방 제품을 찾는 것을 보고 기존 고객용 신제품 라인을 내 성공했고, 자동차 업체는 변화하는 요구에 맞는 신차로 재구매율을 업계 평균 40%에서 65%로 올렸습니다.

**낮은 가치 고객 규칙**

1. 즉시 끊지 않습니다. 경쟁사만 돕게 되므로 서비스·마케팅 비용을 줄입니다. 획득 단계에서 낮은 가치 고객을 거절하기는 불가능하니 세그먼트의 규모와 가치를 계속 모니터링합니다.
2. 사례: 반품이 많은 고객에게는 반품률이 낮은 보석류만 마케팅했고, 일부 고객에게만 무료배송을 제공해 반품이 많으면 이후 무료배송 혜택을 받지 못하게 했습니다.
3. 은행 사례: 한 은행의 시스템이 고객마다 녹색, 노란색, 빨간색 깃발을 표시해 빨간색은 수수료를 반드시 받고, 녹색은 받지 않고, 노란색은 담당자가 판단하게 하여 연 1억 달러의 추가 매출을 냈습니다. 다른 은행은 손해를 보는 고객(전체의 3%)에게 3달러 수수료를 부과해 6개월 만에 1,100만 명 중 45만 명을 줄였습니다.
4. 구현: `service_flag`(green/yellow/red)를 두고 무료배송, 반품 혜택, 프로모션 노출을 제어합니다. 반품·할인 관련 제외 규칙(12·13장)과 같은 방향입니다. 요금·혜택의 차등은 고객 반발과 약관·소비자 보호 규정 문제가 있을 수 있어 위험 항목에 적었습니다.

## 3. 단계별 로드맵

### 1단계 — 시간과 고객 기반 (7, 12, 13장 규칙 기반 버전)

가장 먼저 만들 것입니다. 점수 없이도 "구매 3일 뒤 후기 요청", "60일 미구매 시 복귀 쿠폰"이 동작합니다.

1. **지연 실행**
   - `scheduled_actions` 테이블(워크플로우 ID, 고객, 실행 예정 시각, 상태)을 만들고 `@Scheduled` 작업이 1분마다 실행 예정 건을 처리합니다.
   - 새 액션 타입 `wait`(예: 3일)을 추가합니다. `executeActions`가 `wait`를 만나면 나머지 액션을 예약 건으로 저장합니다.
2. **고객·구매 모델**
   - `customers`: 이메일, 최초·최종 활동 시각, 현재 생애주기 단계, 유입 채널
   - `purchases`: 고객, 금액, 상품 ID, 구매 시각. `event_logs`에서 `purchase` 이벤트가 들어올 때 함께 적재합니다. 이벤트 JSON 필드 이름은 사용 중인 GTM 설정에 맞춰야 하므로 확인이 필요합니다.
3. **생애주기 단계**
   - 2-1절의 5개 세그먼트와 판정 우선순위를 구현합니다. 임계값(90일, 365일, 허니문 기간)은 설정으로 둡니다. 일 단위 배치로 갱신하고, 구매 이벤트가 들어오면 해당 고객은 즉시 재판정합니다. 단계가 바뀌면 `stage_changed` 이벤트를 내보내 기존 워크플로우의 트리거로 씁니다.
4. **새 조건 타입** (`evaluateConditionGroup`에 추가): `stage`, `purchase_count`, `days_since_last_purchase`, `days_until_expected_purchase`
5. **재보충 시점 계산** (2-2절 규칙 6): `customers`에 `typical_interval_days`와 `next_expected_purchase_at`을 두고 배치로 갱신합니다. 우선순위는 ① 본인 구매 간격 중앙값(구매 2회 이상) ② 상품별 전체 고객 중앙값 ③ 운영자가 입력한 상품 기본 주기이고, 어느 방식으로 계산했는지(`interval_source`)를 기록합니다. 발송 시점은 "주기의 N%" 또는 "N일 전" 중 선택합니다.
6. **예약 실행 시 재검사**: 예약 건을 실행하기 직전에 목표 조건(재구매 여부)과 수신 동의를 다시 평가합니다.
7. **통제 그룹**: 워크플로우에 홀드아웃 비율을 설정하고 대상자를 무작위로 나눠 `workflow_holdouts`에 기록합니다. 통제 그룹은 발송하지 않고 목표 조건 달성(재구매)만 추적해 효과를 비교합니다.
8. **`wait` 기준 시각 선택**: 이벤트 발생 시각 또는 이벤트 데이터의 날짜 필드(예: 예약일, 방문일)를 기준으로 대기할 수 있게 합니다. 서비스업 대응용입니다.
9. **모든 구매 후 메시지**: 첫 구매뿐 아니라 매 구매마다 감사·팁·추천 메시지를 보내는 템플릿을 둡니다. 할인 포함 여부는 2단계 이후 고객가치로 결정하고, 1단계에서는 포함/미포함 두 가지 템플릿 중 선택합니다.
10. **기존 결함 정리**: `frequency` 필드 반영, `actionLogic` 사용 여부 결정
11. **템플릿**: 2-1절의 5개 워크플로우 템플릿과 2-2절의 모든 구매 후 메시지 템플릿
12. **재활성화 고객 처리** (2-3절): 유효기간 경과 고객이 구매하면 `reactivated_at`을 기록하고, 설정 기간(기본 90일) 동안 '재활성화 신규'로 취급해 환영 시퀀스를 다시 적용합니다.
13. **재활성화 제외 규칙**: 반품률 5% 이상, 평균 할인율 30% 이상인 고객은 재활성화 대상에서 제외합니다(기본값, 설정 가능). 반품·할인 데이터가 있을 때만 적용합니다.
14. **인센티브 쿨다운**: 고객당 할인·쿠폰 제안은 최소 N일 간격을 둡니다(`last_incentive_at`). 위험 항목 10의 재진입 쿨다운과 함께 구현합니다.
15. **불만 이벤트 트리거**: `complaint` 이벤트(콜센터·문의 접수)를 받으면 즉시 대응 워크플로우를 시작하는 템플릿을 제공합니다. 이벤트 소스가 있을 때만 쓸 수 있습니다.
16. **업종 유형 설정**: 도표 13.1의 다섯 유형(유행, 재보충/버전업, 신중 구매, 회원 가입, 기본) 중 하나를 선택하면 재보충 알림 기본 활성 여부, 90일·365일 임계값 같은 기본값을 추천합니다. 유형별 기본값은 제 제안이며 책에 있는 값이 아닙니다.

### 2단계 — 점수와 고객가치 (8, 9, 13장)

1. `customer_metrics` 테이블: RFM(최근성, 빈도, 금액), 누적 가치, 이탈 위험 점수, 구매 가능성 점수, 계산 시각
2. 일 단위 배치 계산(처음에는 SQL과 규칙 기반 가중치)
3. 새 조건 타입 `score`(지표 이름, 비교, 값)와 점수 등급 조건
4. 점수 등급별 리스트 자동 갱신(`list` 액션 재사용)
5. **충성도 4유형 지표와 마진 기준 가치** (2-2절 규칙 11, 12): `tenure_days`, `category_count`, `referral_count`, `return_rate`, `discount_purchase_ratio`를 배치로 계산하고, 매출이 아니라 마진을 반영한 가치 점수를 만듭니다.
6. **VIP 사은 대상 선정**: 8장의 VIP 기준(가치 순위 상위 10%, 설정값)을 리스트로 만들고 비금전 보상 안내 워크플로우와 연결합니다. 12장의 "고객 약 20%가 매출 60% 이상"은 책이 관찰한 매출 집중도이지 분류 기준이 아닙니다.
7. **첫 구매 시점 가치 예측으로 환영 캠페인 차등**: 예측값이 높은 고객에게 더 큰 혜택과 특별 대우를 제공합니다.
8. **개인별 목표 금액 캠페인**: 고객 평균 주문액 × 설정 계수로 "N원 쓰면 추가 혜택" 메시지를 개인별로 생성합니다.
9. 규칙 기반 페르소나 근사(타락 천사, 되돌아오지 않는 대량 구매자 등)를 세그먼트로 제공합니다.
10. **유지율 리포트** (2-3절): 금액 기준 유지율, 가치 세그먼트별 유지율, 고객 기간별 이탈률과 구성비, 고객 기간 구성을 맞춘 표준화 이탈률, 순 매출 유지율(역이탈), 전년 대비 지출이 줄어든 고객 세그먼트(가치 감소).
11. **이탈 위험 점수(규칙 기반)**: 예상 재구매일 대비 경과 비율, `activity_trend`, `spend_change_rate`, `complaint_count_90d`, `category_count`, `engagement_regularity`의 가중 합입니다. 가중치는 제가 임의로 잡을 기본값이라 통제 그룹 테스트로 조정해야 합니다.
12. **유지 인센티브 상한**: `max_incentive = Y × LTV` 검사를 인센티브 액션에 적용합니다.
13. **가치에 비례한 인센티브 단계**: 가치가 높은 고객에게 더 큰 혜택을 주고, 전화 같은 고비용 접촉은 상위 가치 고객으로 제한합니다.
14. **가치 세그먼트 산정** (2-4절): 최근 12개월 가치(마진 우선, 없으면 매출)의 순위로 상위 10%, 다음 60%, 하위 30%를 분류하고 `customers.value_tier`에 저장합니다. 비율과 창 길이는 설정값입니다.
15. **가치 이동 리포트**: 이전·최근 두 기간의 세그먼트를 비교한 교차표, 7개 세그먼트 인원, 세그먼트별 순손익 가치(순변화 × 고객당 지출)를 매월 계산합니다. 6번(가치 하락) 고객은 이탈 위험 경보로 연결합니다.
16. **가치 기반 전략 템플릿**: 높은 가치는 유지 프로그램, 중간 가치는 카테고리 확장 캠페인과 구매 빈도 우대, 낮은 가치는 저비용 채널만 사용하고 프로모션 제외.
17. **서비스 수준 플래그**: `service_flag`(green/yellow/red)로 무료배송, 반품 혜택, 프로모션 노출을 제어합니다. 요금·혜택 차등은 위험 항목 14 확인 후 적용합니다.
18. **중간 가치 성장 대상**: 한 카테고리만 구매한 중간 가치 고객 세그먼트를 만들어 교차 판매 대상으로 씁니다(`category_count` 사용).

### 3단계 — 모델 도입 (6, 9장)

1. 군집화와 구매·이탈 확률 모델은 Java 내부 구현보다 **별도 Python 배치/서비스**가 적합합니다. 결과를 `customer_metrics`와 `segments`에 쓰기만 하면 엔진은 변경이 필요 없습니다.
2. 학습에 필요한 데이터량은 확인이 필요합니다. 구매 이력이 충분하지 않으면 2단계의 규칙 기반 점수를 유지하는 편이 낫습니다.
3. 모델 성능은 목표 조건(`goal_groups`)과 전환 데이터로, 통제 그룹과 비교해 측정합니다.
4. 군집 특성값은 고객이 폼에 밝힌 선호가 아니라 구매·열람 행동을 우선합니다(2-2절 규칙 9). 입력 특성은 평균 주문액, 구매 간격, 채널, 반품률, 할인 구매 비중, 카테고리, 최초 유입 경로·시기입니다.
5. **이탈 점수와 영향 요소 순위** (2-3절 규칙 7): 이탈 확률 모델을 매일 고객별로 계산하고, 변수 중요도를 리포트로 보여줍니다. 요소별 대응 전략(예: 불만 이력 → 재전화, 가격 민감 → 계약 종료 전 협의)을 통제 그룹으로 테스트합니다.

### 4단계 — 분석·추천·광고 연동 (5, 10, 11장)

1. 채널별 획득비용 대비 고객가치 리포트(광고비 입력 화면 포함)
2. 함께 구매 상품 기반 추천을 메시지 변수로 제공
3. 상위 점수 고객 리스트의 CSV·광고 플랫폼 내보내기
4. **옴니채널**: `purchases.channel`, `customers.region`, `channel_count` 지표, 지역+점수 세그먼트(예: 신규 매장 반경 내 고가치 고객 초청 + 개장 2일 전 리마인드)
5. **신제품·재고 소개**: 상품 속성(사이즈 등)과 고객 관심·선호 사이즈로 대상을 좁히는 세그먼트
6. **충성도 포인트 원장**(선택): 고객사가 포인트 제도를 운영하지 않는 경우에만 필요. 운영 중이면 쿠폰·적립금 발급 웹훅으로 연동
7. **구매 전 퍼널 세분화**: 예상고객을 가입, 상품 조회, 장바구니 등 행동 단계로 나누는 기능(11장 리마케팅과 함께)
8. **다채널 재활성화**: 알림톡 외에 우편·광고 타깃용 내보내기(수용 가능성 상위 고객만)와 채널별 접촉 빈도 상한

## 4. 데이터 모델 초안 (1~2단계)

```sql
-- 다음 마이그레이션 번호는 V2 부재 여부를 확인한 뒤 결정
CREATE TABLE customers (
  id BIGSERIAL PRIMARY KEY,
  email VARCHAR(255) NOT NULL UNIQUE,
  first_seen_at TIMESTAMP, last_seen_at TIMESTAMP,
  lifecycle_stage VARCHAR(30), stage_changed_at TIMESTAMP,
  acquisition_channel VARCHAR(100),
  typical_interval_days INT, next_expected_purchase_at TIMESTAMP,
  interval_source VARCHAR(20),    -- individual / crowd / manual
  region VARCHAR(100),
  reactivated_at TIMESTAMP,       -- 유효기간 경과 후 재구매한 시각
  last_incentive_at TIMESTAMP,    -- 인센티브 쿨다운
  value_tier VARCHAR(10),         -- high / mid / low (상위 10 / 다음 60 / 하위 30)
  service_flag VARCHAR(10),       -- green / yellow / red (낮은 가치 고객 서비스 정책)
  marketing_consent BOOLEAN DEFAULT false
);
CREATE TABLE purchases (
  id BIGSERIAL PRIMARY KEY,
  customer_id BIGINT REFERENCES customers(id),
  amount NUMERIC(14,2), product_id VARCHAR(100),
  channel VARCHAR(20),            -- online / offline (옴니채널)
  purchased_at TIMESTAMP, event_id BIGINT REFERENCES event_logs(id)
);
CREATE TABLE product_cycles (     -- 상품별 재보충 주기
  product_id VARCHAR(100) PRIMARY KEY,
  manual_cycle_days INT,          -- 운영자 입력 (3순위)
  crowd_cycle_days INT,           -- 전체 고객 중앙값 (2순위, 배치 계산)
  updated_at TIMESTAMP
);
CREATE TABLE workflow_holdouts (  -- 통제 그룹
  workflow_id BIGINT REFERENCES workflows(id) ON DELETE CASCADE,
  customer_email VARCHAR(255),
  grp VARCHAR(10),                -- test / control
  assigned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (workflow_id, customer_email)
);
CREATE TABLE customer_metrics (
  customer_id BIGINT PRIMARY KEY REFERENCES customers(id),
  recency_days INT, frequency INT, monetary NUMERIC(14,2),
  value_score NUMERIC, churn_risk NUMERIC, purchase_propensity NUMERIC,
  tenure_days INT, category_count INT, channel_count INT, referral_count INT,
  return_rate NUMERIC, discount_purchase_ratio NUMERIC, avg_discount_rate NUMERIC,
  spend_change_rate NUMERIC, activity_trend NUMERIC,
  engagement_regularity INT, complaint_count_90d INT,
  segment VARCHAR(50), computed_at TIMESTAMP
);
CREATE TABLE value_snapshots (    -- 가치 이동 행렬용: 기간별 가치와 세그먼트 보관
  customer_id BIGINT REFERENCES customers(id),
  period_end DATE, window_months INT DEFAULT 12,
  value NUMERIC(14,2), tier VARCHAR(10),   -- none / low / mid / high
  PRIMARY KEY (customer_id, period_end)
);
CREATE TABLE scheduled_actions (
  id BIGSERIAL PRIMARY KEY,
  workflow_id BIGINT REFERENCES workflows(id) ON DELETE CASCADE,
  customer_email VARCHAR(255), remaining_actions TEXT, event_data TEXT,
  run_at TIMESTAMP NOT NULL, status VARCHAR(20) DEFAULT 'pending'
);
CREATE INDEX idx_scheduled_due ON scheduled_actions(status, run_at);
```

## 6. 위험과 확인 필요 사항

1. **개인정보**: 고객 이메일·구매 이력을 점수화하므로 개인정보 처리방침과 마케팅 수신 동의 확인이 필요합니다. 동의하지 않은 고객에게는 발송하지 않는 조건이 필요합니다.
2. **발송 비용**: 알림톡 등 건당 비용이 있습니다. 점수 기반 대량 발송은 잘못 설정하면 비용이 급증하므로 일일 발송 상한과 승인 단계가 필요합니다.
3. **동기 처리**: 지금은 이벤트 수신 요청 안에서 모든 워크플로우를 실행합니다. 워크플로우가 늘면 응답이 느려지므로 1단계에서 비동기 처리 전환을 검토합니다.
4. **다중 사용자 분리**: 확인한 범위에서는 사용자(테넌트) 구분이 보이지 않습니다. 고객 테이블을 추가하기 전에 단일 사용자 시스템인지 확인이 필요합니다.
5. **구매 이벤트 형식**: 현재 수집되는 GTM 이벤트에 금액·상품 ID가 들어오는지 확인되지 않았습니다. 1단계의 전제 조건입니다.
6. **업종·데이터량**: 이탈 정의와 모델 적용 가능 여부는 업종과 구매 데이터량에 달려 있습니다.
7. **할인 비용과 마진**: 개인별 할인과 목표 금액 혜택은 마진을 깎습니다. 책의 보상 중독자 사례처럼 매출은 크지만 마진이 낮은 고객이 있으므로, 할인 한도를 마진 기준으로 두고 통제 그룹으로 실제 증분 효과를 확인해야 합니다.
8. **광고성 메시지 법규**: 알림톡 등 광고성 메시지는 수신 동의와 야간 발송 제한 같은 관련 법규의 적용 대상일 수 있습니다. 정확한 요건은 확인하지 못했으므로 구현 전에 법무 또는 메시지 발송 사업자의 기준을 확인해야 합니다.
9. **이벤트 외 날짜 필드**: 서비스업의 예약일 기준 발송은 이벤트에 해당 날짜 필드가 들어와야 가능합니다.
10. **순환 구조의 재진입**: 그림 12.1처럼 구매 후는 고리입니다. 고객이 이탈 위험에서 다시 반복/활동으로 돌아오면 같은 워크플로우에 다시 들어올 수 있어야 합니다. 기존 `onlyFirstTime` 옵션을 켜면 고객당 한 번만 처리되므로, 단계 기반 워크플로우는 이 옵션을 끄고 "같은 고객은 N일 안에 같은 워크플로우에 재진입하지 않음" 같은 쿨다운 규칙을 새로 두는 것을 제안합니다. 또 워크플로우를 런칭할 때 이미 해당 단계에 있는 고객을 처리할지(기존 런칭 시 처리 방식을 단계 조건에도 적용할지)를 결정해야 합니다.
11. **선제 인센티브의 길들임**: 이탈 위험 고객에게 할인을 자주 주면 고객이 할인을 기다리게 됩니다(책이 지적한 선제 방식의 단점). 인센티브 쿨다운과 통제 그룹으로 확인합니다.
12. **인센티브 상한 해석**: 13장의 `X = Y × LTV`가 대상 1인당 한도인지 보존 고객 1인당 한도인지 본문 표현이 모호합니다. 예시 계산은 대상 1인당으로 읽힙니다. 원문 확인이 필요합니다.
13. **이탈 관련 데이터 소스**: 방문·세션 이벤트, 불만·문의, 반품·할인 정보가 현재 수집되는지 확인하지 못했습니다. 없으면 해당 지표는 구매 이력 기반 지표로 대체하고, 이탈 점수의 정확도가 낮아질 수 있습니다.
14. **가치 기반 차등 대우의 신뢰와 규정**: 낮은 가치 고객에게 요금 부과, 무료배송 제외, 서비스 수준 하향을 적용하면 고객 반발이 있을 수 있고 약관 고지나 소비자 보호 관련 규정이 적용될 수 있습니다. 책의 사례는 미국의 은행·유통업이며 국내 규정은 확인하지 못했습니다. 우선 높은 가치 고객에게 혜택을 더 주는 방향부터 적용하고, 불이익을 주는 방향은 확인 후에 도입할 것을 제안합니다(제 제안).
15. **가치 이동 행렬에 필요한 데이터 기간**: 12개월 창 두 개를 비교하므로 24개월 이상의 구매 이력이 필요합니다. 이력이 짧으면 창 길이를 줄여야 하고(예: 3~6개월), 적정 창은 재구매 주기가 긴 업종일수록 길어야 합니다.
